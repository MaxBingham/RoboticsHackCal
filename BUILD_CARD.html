Build card · Robotics Hackathon at Cal · Aug 30–31, 2026

Feedbot

A robot arm that feeds you peanuts. Trained from zero in one weekend — we taught an SO-101 the motion by hand, then let it run on its own: it picks a peanut off the table and holds it up to your mouth, no human on the controls.

What existed before the hackathon

Nothing project-specific — the team started from scratch. No prior code, datasets, or trained models. Everything preexisting was off-the-shelf: the SO-101 leader/follower arm kit, the open-source LeRobot library, public pretrained checkpoints, and the ElevenLabs API (all listed under External assets below).

What the team added during the event

  • Demonstration datasets — teleoperated peanut-handoff episodes recorded with the leader arm across multiple sessions (single robot-mounted camera, 640×480 @ 30 fps), iterated over three dataset versions plus a hand-cleaned variant.
  • Two trained ACT policies — Action Chunking Transformers trained 20,000 steps each: one on the 29-episode v3 dataset, one on all 57 episodes combined.
  • Hardware deployment — a working closed-loop rollout on the physical arm via lerobot-rollout, with tuned per-step safety limits.
  • Voice-control stack (incomplete) — an ElevenLabs conversational agent with a locked-down tool interface: an approved-task allowlist, a hardware-launch bridge, and a spoken emergency stop.
  • SmolVLA experiments — a single-camera adapter and joint-unit fix for a public pick-and-place checkpoint; the team selected ACT after qualitatively more reliable runs, but did not complete a controlled comparison.
  • Encoder-pretraining experiment — a visual encoder trained on the World Context industrial video dataset with a weight-transfer script into SmolVLA; not carried into the final policy.

Central result

An ACT policy trained only on the team's own demonstrations autonomously performs the peanut pickup-and-present task on the physical SO-101.

Evidence: live hardware rollouts on Aug 30 using the act_so101_nut_handoff_v3 checkpoint — the arm executes the pickup-and-present motion end to end with no teleoperation, with the per-step safety limiter engaging as designed. The exact verified command is committed to the repository README. Evidence is qualitative (observed successful runs); no quantitative success-rate evaluation was completed.

Limitations, failures & unfinished work

  • Voice integration unfinished. The ElevenLabs agent, tool allowlist, and emergency stop were built and the launch path was repaired, but a full voice-to-robot run was never completed at the event. Demo runs were launched from the command line.
  • No quantitative evaluation — success is demonstrated by observed runs, not a measured success rate over repeated trials.
  • Small dataset — 29–57 episodes with one camera; behavior is sensitive to starting pose and scene changes relative to the demonstrations.
  • Cleaned dataset unused — a hand-filtered 28-episode v3 variant was prepared, but no checkpoint was retrained on it.
  • SmolVLA path failed on this rig — the public two-camera checkpoint could not be made reliable on the one-camera setup and was dropped.
  • Encoder-transfer experiment inconclusive — World Context pretraining was never benchmarked against the baseline.
